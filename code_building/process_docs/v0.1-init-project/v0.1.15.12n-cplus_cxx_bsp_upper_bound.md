# v0.1.15.12n - BSP C+ / C++ Upper-Bound 实验

## 目标

本轮不急于下沉 dInfer/vLLM 源码，而是在独立实验脚本里继续把 BSP 路线的收益上限跑出来。

两条新增路线：

- C+ / E：`C12-BSP-CrossLayerSP`，把 SP hidden state 跨 sparse decoder layer 继续传递，只在 attention 输入和最后 sparse layer 输出处 gather 回 full layout。
- C++ / F：`C12-BSP-AllReduceFullProbe`，保留 EP dispatch 和本地 expert compute，但跳过 native reduce_scatterv combine，用一个 EP full all-reduce 的 full-token buffer 做 upper-bound collective probe。

本轮仍保持约束：

- 不引入 Scheme3 payload 改造。
- 不改变 EB/s_mask 算法。
- 不修改 dInfer/vLLM 源码。
- 所有结论基于 `codex_coding/src/bench_bsp_moe_dp2.py` 的独立 monkey-patch 实验。

## 代码改动

修改文件：

- `codex_coding/src/bench_bsp_moe_dp2.py`

新增或补齐内容：

- `SPHiddenState` dataclass，用于在 patched decoder layer 之间携带 SP hidden state。
- `make_bsp_cross_layer_sp_decoder_forward(...)`：
  - 如果输入是 full tensor，先在 attention 前正常 full layout。
  - MoE 前 chunk 到 SP。
  - MoE 后 residual 和后续 sparse layer 输入继续保持 SP。
  - 下一层 attention 前才 gather normalized SP hidden 到 full layout。
  - 最后一个 sparse layer 返回 full tensor，保证外层 `model.model.norm` 可接收普通 tensor。
- `make_bsp_allreduce_full_decoder_forward(...)`：
  - 使用 native EP dispatch。
  - 直接调用 `experts.quant_method.apply(...)` 做本地 expert compute。
  - 不调用 native combine。
  - 将 residual/shared local slice 加到 global partial buffer 对应区间。
  - 用 `get_ep_group().all_reduce(full_buffer)` 汇合 full-token buffer。
  - 切回当前 DP rank 的 token 区间。
- compare mode 增加：
  - `E) C12-BSP-CrossLayerSP`
  - `F) C12-BSP-AllReduceFullProbe`
- component timing 增加：
  - `moe.input_norm_sp`
  - `moe.post_attn_norm_sp`
  - `moe.ep_full_all_reduce`
  - `ep_full_allreduce_payload`

组件解释：

- E 的 dispatch/TP gather payload 与 C 相同，因此 E 的收益不是新的字节量下降，而是 SP layout 生命周期延长后，native/quant/combine 维持在 C 级别，同时减少 full/SP 往返的整体调度开销。
- E component timing 下 `tp_all_gather` count 仍为 `5054`，但其语义已经从“每层 MoE 输出后立刻 gather”变为“下一层 attention 输入前 gather normalized hidden”。这说明真正的源码下沉还需要进一步把 attention 侧 layout 边界做成原生路径，才可能继续减少同步点。
- F 的 `native_forward` 降到 `29.195 ms/fwd`，说明跳过 native combine 和显式 TP gather 的方向有真实 upside。
- F 同时引入 `1311.020 MB/fwd` 的 EP full all-reduce payload，因此它不能作为 production 方案，只能证明“更少同步点 / combine-gather 重排”值得做。

## Quality Smoke

配置：`batch=32, gen=32, num_runs=1`，开启 snippets。

观察：

- E/F 在三个 verifiable prompt 上都输出了连贯的解题文本。
- E 与 B/C 类似，存在局部 markdown/formula 格式差异。
- F 输出也连贯，但个别 snippet 有公式字符差异。

结论：

- smoke 没有发现 E/F 的灾难性语义崩坏。
- 这不等价于完整质量评估；源码下沉前仍需要跑既定质量集。

## 当前结论

- E / C+ 是当前最优 BSP 方向：两轮 C12 no-timing 平均 `75.73 -> 71.80 ms/fwd`，约 `-5.20%`，明显高于此前 C 的 `-2.10%`。
- C+ 的核心价值是延长 SP layout 生命周期，而不是继续减少单次 MoE payload。
- F / C++ full all-reduce probe 说明“把 EP reduce_scatterv combine + TP all_gather 合并/重排成更少同步点”有潜力：平均 `-4.32%`，但 full all-reduce payload 太大，不应直接采用。
- M3 EB 三路径仍保持为兼容性接口结论，不应单独改变 EB 算法；本轮 A-F path counts 均保持一致，说明 E/F 路线不会天然冲突 EB。

## 下一步建议

源码下沉优先级：

1. 优先下沉 E / C+：
   - 在 dInfer/vLLM 原生层表达 `SPHiddenState` 或等价 layout metadata。
   - sparse MoE 后 residual/norm 保持 SP。
   - attention 边界前 gather。
   - 最后 model norm 前保证 full tensor。
2. 其次设计 production 版 C++ collective：
   - 不采用 raw full all-reduce 作为最终方案。
   - 目标是 hierarchical collective：EP reduce_scatterv combine 与 TP all_gather 的融合或重排。
   - 需要减少同步点，同时避免 F 的 `1311 MB/fwd` payload。
3. M3 暂时不作为性能主线：
   - hot_update `pop[E]` all-reduce 兼容性已经成立。
   - 真正收益要等 routing/EB combine 前移到 token-level AgRs gather 之前。
