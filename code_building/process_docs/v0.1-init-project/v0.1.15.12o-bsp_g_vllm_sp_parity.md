# v0.1.15.12o - BSP-G vLLM SP-Parity 实验

## 目标

本轮阶段命名为 BSP-G；F2 / 跨 group collective 设计保留为 BSP-H，暂不进入。

BSP-G 的目标是在不下沉 dInfer/vLLM 源码、不改 EB/s_mask 算法、不引入 Scheme3 payload 改造的前提下，先把 vLLM SP-parity 里能搬的局部优化吃干净：

- E / C+ 已经把 MoE 后 residual/norm 到下一层 attention 前保持 SP。
- G 进一步把 attention output projection 的 TP all-reduce/full layout 输出改成 TP reduce-scatter/SP layout 输出。
- 这样 attention 后的 residual、post-attention norm、MoE 可以直接消费 SP hidden state，减少 full/SP 反复切换。

## 代码改动

修改文件：

- `codex_coding/src/bench_bsp_moe_dp2.py`

新增或补齐内容：

- `AttnSPResult` dataclass，用于在 patched attention 与 decoder layer 之间携带 SP output metadata。
- `make_attention_reduce_scatter_forward(attention)`：
  - attention dense projection 先得到 TP-local partial output。
  - 用 TP reduce-scatter 沿 token 维切分输出。
  - 返回 SP layout 的 attention output，而不是 full layout tensor。
- `make_bsp_g_attn_rs_decoder_forward(...)`：
  - 接收 `AttnSPResult`。
  - 在 SP layout 上做 residual、post-attention norm、MoE。
  - 继续复用 C+/E 的跨 sparse layer SP 生命周期。
- `setup_bsp_g_attn_rs(...)`。
- compare mode 新增：
  - `G) C12-BSP-G-AttnReduceScatterSP`
- component timing 新增：
  - `attn.tp_reduce_scatter`
  - `attn_rs_payload`

## Component Timing

结果文件：

- `codex_coding/results/bsp_moe_bspg_c12_component_20260428.json`

说明：

- component timing 用于机制归因，不应和 no-timing e2e 绝对值直接混比。
- 本轮 component timing 下 A `79.63 ms/fwd`，E `81.09 ms/fwd`，G `81.45 ms/fwd`，F `77.32 ms/fwd`；该排序受 instrumentation 扰动，不能推翻 no-timing e2e 的 G 最快结论。

关键 bucket：

| Component / Payload | A | E | G | F |
|---|---:|---:|---:|---:|
| `moe.bsp_chunk` ms/fwd | n/a | 0.872 | 0.003 | 1.035 |
| `moe.bsp_chunk` count | n/a | 5320 | 266 | 5054 |
| `attn.tp_reduce_scatter` ms/fwd | n/a | n/a | 5.020 | n/a |
| `attn_rs_payload` MB/fwd | n/a | n/a | 661.502 | n/a |
| `dispatch_payload` MB/fwd | 826.877 | 206.719 | 206.719 | 206.719 |
| `tp_gather_payload` MB/fwd | n/a | 165.375 | 165.375 | n/a |
| `ep_full_allreduce_payload` MB/fwd | n/a | n/a | n/a | 1311.020 |

机制解释：

- G 没有进一步减少 MoE dispatch/combine payload；它和 E 一样保持 `dispatch_payload=206.719 MB/fwd`、`tp_gather_payload=165.375 MB/fwd`。
- G 的关键收益是把 `moe.bsp_chunk` 从 E 的 `5320` 次、`0.872 ms/fwd` 降到 `266` 次、`0.003 ms/fwd`，说明 attention 后直接产出 SP layout 后，后续 residual/norm/MoE 不再反复 full-to-SP chunk。
- G 新增 `attn.tp_reduce_scatter=5.020 ms/fwd` 和 `attn_rs_payload=661.502 MB/fwd`，所以它不是“免费减少通信”，而是把 attention output 的同步边界改造成更有利于后续 SP 生命周期的形态。
- G 的真实收益来自 layout 生命周期延长和同步点位置移动；当前 Python monkey-patch 仍没有解决 MoE combine + TP gather 的根问题。

## 当前结论

- BSP-G 是目前不进入 BSP-H/F2 前，最值得保留的收益兑现路线。
- G 的平均 C12 no-quality latency 为 `69.53 ms/fwd`，相比 A baseline `76.03 ms/fwd` 提升 `8.55%`。
- G 比 E/C+ 继续快 `2.93%`，说明“attention 输出直接 reduce-scatter 到 SP layout”比“attention 后再 chunk”更接近 vLLM SP-parity 应有收益。
- EB/s_mask 与 G 路线兼容：C12 path counts 全部一致，没有 cold/hot_update/hot_skip 调度改变。
- G 仍没有解决 MoE combine + TP gather 的 payload 问题；BSP-H/F2 仍然需要面向 hierarchical/fused collective 设计，但应在 BSP-G 下沉/质量确认后再做。

## 下一步建议

优先级建议：

1. BSP-G 下沉设计优先于 BSP-H。
2. 把 attention output reduce-scatter + SPHiddenState layout metadata 做成源码级 feature flag，而不是继续堆 monkey-patch。
3. 源码化前必须补完整质量集，因为 G 改变了 attention output layout 边界，small smoke 不足以做生产质量结论。
4. BSP-H/F2 继续保留为后续方向，目标仍是减少或融合 `EP reduce_scatterv combine + TP all_gather`，但不要在当前阶段提前引入。
