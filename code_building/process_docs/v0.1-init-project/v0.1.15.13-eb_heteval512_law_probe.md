# v0.1.15.13 — EB HetEval512 Law Probe

## Purpose

Explore whether Expert Budgeting (EB) exposes stronger dLLM-MoE regularities beyond its already accepted role of reducing unique active experts / HBM expert weight loads.

This is an observation experiment, not a source landing or correctness proof.

## User Intent

- Use the historical `HetEval-512` large heterogeneous batch setting.
- Treat EB as an already usable mechanism; do not spend this phase proving exact numerical equivalence.
- Look for larger regularity space:
  - active expert reduction,
  - temporal `S_mask` stability,
  - block phase structure,
  - layer differences,
  - static/global popularity vs current EB selection,
  - request grouping potential for future serving policies.

## Measurement Scope

The script will patch routing only to observe:

- actual EB `S_mask` and actual routed top-k expert ids,
- counterfactual no-EB top-k expert ids on the same logits,
- optional no-EB top-8 expert ids,
- per-layer/per-block/per-forward active expert set sizes,
- EP-partition load skew,
- adjacent and cross-block Jaccard of `S_mask`,
- simple request grouping summaries for selected layers.

Only representative TP ranks (`tp_rank=0` in each DP group) write full routing traces, to avoid counting TP-duplicated logical demand multiple times.

## Non-Goals

- No EB algorithm change.
- No BSP/SP layout change.
- No source-downshift.
- No quality judgment beyond assuming the known EB semantic tolerance.
- No performance claim from this instrumented run, because per-layer CPU summaries add synchronization overhead.

## Stop Conditions

- Stop and report if `HetEval512` config cannot be reconstructed.
- Stop and report if 8-GPU distributed initialization fails.
- Stop and report if the run hangs or path counts differ across ranks in a way that invalidates the trace.

## Expected Interpretation

Useful evidence would be:

- EB active expert set is much smaller than no-EB counterfactual.
- `S_mask` becomes more stable within block, especially after early iterations.
- Layer-wise `S_mask` size/stability is not uniform.
- Current EB `S_mask` is better aligned to actual per-block demand than a global popularity set.
- Request grouping by expert demand has a measurable active-union or load-skew effect.

### Active Expert Reduction

Across 10,070 traced layer-forward records:

| Metric | Mean | P50 | P90 | P95 |
|---|---:|---:|---:|---:|
| EB top4 unique active experts | `197.98` | `200` | `216` | `221` |
| no-EB top4 unique active experts | `251.22` | `253` | `256` | `256` |
| no-EB top8 unique active experts | `254.59` | `256` | `256` | `256` |

Mean reduction:

- EB vs no-EB top4: `21.19%`
- EB vs no-EB top8: `22.23%`

Interpretation: in HetEval512, no-EB nearly activates the full 256-expert pool on each layer-forward. EB keeps the active set around 198 experts on average, which is still large but materially below full activation.

### Control Sets

Weighted coverage of current no-EB top4 demand:

| Set | Mean coverage |
|---|---:|
| EB `S_mask` | `0.9681` |
| offline global-popularity same-size set | `0.9704` |
| previous call's `S_mask` | `0.9658` |
| previous block cold `S_mask` | `0.9328` |
| random same-size set | `0.7733` |

Interpretation:

- EB is not random pruning; same-size random expert sets are far worse.
- At HetEval512 scale, a static global-popularity same-size oracle is slightly better than current EB in coverage. This suggests large heterogeneous batch demand is highly stable/global.
- Previous-call `S_mask` is almost as good as current EB, supporting aggressive hot-skip or delayed update.
- Previous-block cold `S_mask` remains useful but weaker, suggesting cross-block reuse needs correction.

### Request Grouping

Request grouping was computed on cold records for layers 0/9/18 with group size 64.

| Metric | EB | no-EB top4 |
|---|---:|---:|
| per-request unique expert mean | `35.92` | `37.36` |
| all-request union mean | `200.93` | `251.22` |
| natural group union mean | `168.97` | `197.85` |
| random group union mean | `193.69` | `230.36` |
| centroid-sorted group union mean | `176.61` | `209.24` |

Interpretation:

- EB reduces full-batch union active experts strongly.
- Natural prompt order is already clustered better than random; this may be an artifact of HetEval512 prompt construction, not a general serving property.
- The naive centroid grouping heuristic was worse than natural order for EB (`+4.52%` union), so request scheduler research needs a better similarity metric than expert-id centroid.

### EP Load Skew

Mean EP-partition load skew:

| Route | Mean | P50 | P90 | P95 |
|---|---:|---:|---:|---:|
| EB top4 | `3.118` | `2.641` | `4.260` | `5.502` |
| no-EB top4 | `2.970` | `2.547` | `4.033` | `5.116` |
| no-EB top8 | `2.882` | `2.569` | `3.881` | `4.497` |

Interpretation: current EB reduces active experts but slightly worsens EP load skew under linear expert placement. This confirms two objectives must be separated:

- reduce unique active experts / HBM weight loads,
- balance EP-rank load / slow-rank tail.

EB alone optimizes the first, not necessarily the second.

## Conclusions

1. The historical `HetEval512` C12 configuration is recovered and reproducible.
2. EB's primary effect is confirmed at large batch: no-EB top4 activates nearly all experts, while EB reduces average active experts by about `21%`.
3. `S_mask` has very strong adjacent stability; previous-call reuse is nearly as predictive as current EB.
4. Large-batch demand contains a strong global-popularity structure. This creates a new research direction: combine EB with global or slowly updated expert popularity priors.
5. Layer differences are real; per-layer budget/adaptive policy is justified.
6. EB active-expert reduction and EP load balancing are different, sometimes conflicting objectives.
7. Simple request grouping by centroid is not enough; future scheduling work needs a better demand-similarity metric.

## Next Questions

- Is global-popularity superiority an artifact of using one fixed HetEval512 run, or does it transfer across held-out prompt batches?
- Can a hybrid policy `global prior + EB correction` reduce active experts more than EB without quality loss?
- Can per-layer `K_target` shrink layers 7/9/16/17 while keeping layers 0/1 conservative?
- Can request grouping optimize active expert union without worsening EP load skew?
- Does expert placement/replication recover EB's EP-skew penalty while preserving active-expert reduction?

## Follow-up Plan: EB-aware EPLB Direction

User decision on 2026-04-28:

- Do not prioritize layer-wise `K_target` tuning yet.
- Current EB already has per-layer independent `S_mask`, per-layer `K_init`, and cold-path self-correction through `q_major` / `quality_floor`.
- Treat `K_target=40` as an initial seed budget, not the main research lever.
- Prioritize the interaction between EB and EPLB-style expert placement/load balancing.

Working hypothesis:

EB reduces unique active experts / HBM expert weight loads, but it does not directly optimize EP-rank load balance. In the HetEval512 trace, EB reduces no-EB top4 unique active experts from `251.22 / 256` to `197.98 / 256` (`21.19%` reduction), while mean EP skew slightly increases from `2.970` to `3.118` under linear expert placement. This makes EB-aware EPLB a natural complement rather than a competing mechanism.

Potential paper mechanism:

- EB provides a per-layer/block active expert set and exposes stable expert demand.
- EPLB remaps or sparsely replicates the remaining hot experts to reduce slow-rank tail.
- dLLM block-level repeated forwards and `S_mask` stability allow placement/replica decisions to be amortized across multiple hot-skip iterations.
- Global popularity prior can guide slow-path/static placement, while block-local EB corrects online demand.

Candidate mechanisms to evaluate before source implementation:

1. EB-aware static remap: use historical EB trace to distribute hot experts more evenly across EP ranks than expert-id linear placement.
2. Sparse hot-expert replication: replicate only the small set of persistent high-demand experts, then select the least-loaded replica at block/local scheduling time.
3. Block-local replica selection: choose expert copies at cold path or block start and reuse the plan during hot-skip.
4. Load-aware request grouping: group requests by weighted expert-demand overlap while constraining EP-rank skew.

Required front-loaded experiments:

1. Skew-latency correlation: collect per-layer/per-forward expert token counts, EP-rank load, and MoE latency to verify whether load skew predicts slow-rank tail.
2. Offline placement upper bound: compare current linear placement, random balanced placement, popularity-balanced placement, co-activation-aware placement, and oracle per-layer placement.
3. Replica budget sweep: simulate top-1%/2%/5%/10% hot expert replication and measure max EP load reduction versus HBM overhead.
4. Global-prior transfer: build popularity prior on one prompt slice and validate coverage/skew reduction on held-out prompts or later blocks.
5. Scheduler interaction: test whether request grouping can reduce active expert union without worsening EP skew.

Guardrail:

EPLB should not change router semantics or EB quality logic. It should only change where selected experts are placed, replicated, or executed.
