## Result

当前最关键的事实发生了更新：

- “正式 dInfer 曾经跑通”仍然是成立的历史事实；
- 但“当前环境还能直接复现 formal run”已经不能成立；
- 也就是说，项目状态已经从“可以直接继续 benchmark sweep”变成了“需要先做环境回归定位或恢复可复验状态”。

同时，本轮也确认了一个旧疑点已经不是当前阻塞项：

- 之前记录里的 `outlines/outlines_core` 版本冲突，在当前环境快照下并不存在，因为 `outlines_core` 现在是 `0.1.26`。

## Next Steps

- 下一步更合理的主线不再是直接扩 benchmark，而是先定位当前回归：
  - 为什么 `dinfer` 顶层导入会在当前环境下触发 `std::bad_alloc`
  - 这是否与 `torch 2.9.1+cu128` 的版本漂移有关
  - 是否是 `dinfer` 顶层导入链中某个 `vllm/sglang` 相关初始化在当前二进制组合下触发异常
- 在 formal route 被恢复之前，不建议直接继续做 `cache/use_bd/threshold/gen_length/compile` 的 sweep。
