Date: 2026-04-29  
Owner: Codex + User  
Scope: Move from offline EPLB analysis into dInfer source-path implementation and validation.

---

## Goal

Land EB-aware EPLB capabilities in dInfer source path with strict semantic guardrails:

- Do not change router semantics.
- Do not change EB quality logic (`S_mask` construction / path schedule).
- Only optimize expert placement and execution mapping.

---

## Implementation Plan

1. P1 (current): static placement source landing
   - Add optional external expert-map loading in `LLaDA2MoeModelLM` load path.
   - Keep linear placement as default and hard fallback.
   - Ensure per-layer mapping and local-index remap are consistent.

2. P2: runtime EPLB wiring in source path
   - Mainline `enable_eplb / expert_load_view / logical_to_physical_map / logical_replica_count` controls.
   - Keep feature-flagged and no-op by default.

3. P3: sparse replication (start at 5%)
   - Add block-local replica selection policy compatible with EB.
   - Preserve output semantics.

4. P4: online A/B validation
   - Compare baseline vs P1 vs P1+P3 on C12-like workload.
   - Report latency and quality.

---

## Validation Gates

P1 must pass before P2:

1. Model can load with and without external map.
2. Fallback path is safe when map invalid/missing.
3. C12 EB path-count invariant remains unchanged.
4. Basic quality smoke shows no regressions.

---

## Rollback Conditions

Revert to linear placement immediately if:

1. Per-layer expert-map integrity check fails.
2. Local expert packing shape mismatch occurs in any layer.
3. C12 path counts drift from the established invariant.

### 2026-04-30 01:50 CST — Pre-archive for P1/P5 联合编排（同源 physical id 编排）

目标:

- 落地 P1/P5 联合编排第一版，消除“replica 开启时忽略非 identity external map”的临时保护逻辑。
- 不改变 EB 算法语义（`s_mask`、cold/hot path、routing 规则均不变）。
- 保持 `physical->logical` 语义与 vLLM EPLB 初始规则一致，仅重排 physical id 的 rank 归属。

设计要点:

1. 维持 canonical `physical_to_logical`：
   - `pid < num_logical` 对应逻辑专家 `pid`
   - 冗余 `pid >= num_logical` 对应 `pid-num_logical`（mod）
2. 当存在 external map（P1）且启用冗余物理专家（P5）时：
   - base 256 个 physical id (`0..255`) 按 external map 指定 rank 放置；
   - 冗余 physical id (`256..`) 采用按 EP rank 轮转分发（round-robin）；
   - 每层每 rank 形成统一的 `per_layer_global_physical` 与 `per_layer_logical_for_local`，用于权重装载与 `expert_map` 写回。
3. runtime EPLB `logical_to_physical_map / logical_replica_count` 仍可复用 canonical 初始构造；
   - 因为 logical↔physical 对应未变，变化仅在 physical id 归属 rank。
