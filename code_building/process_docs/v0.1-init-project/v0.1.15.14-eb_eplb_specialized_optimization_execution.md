## Stage Results

### Stage 1 — Skew-Latency correlation

Direct correlation from existing per-forward timing reference (`dp2_block_start_timing.json`):

- Pearson(skew, MoE ms): `0.0490`
- Spearman(skew, MoE ms): `0.0242`

Interpretation:

- Under this specific timing reference, simple L1-skew vs total-MoE-ms direct coupling is weak.
- This does **not** invalidate load balancing value; it indicates the current timing proxy is too coarse (single-layer skew proxy + aggregated MoE timing, short run length).

Trace-wide load proxy (linear placement):

- EB p95 max-load-fraction: `0.2695`
- no-EB p95 max-load-fraction: `0.2670`

Interpretation:

- EB slightly worsens load-tail under linear placement, consistent with previous EP-skew findings.

---

### Stage 2 — Offline placement upper bound

Static placement comparison on EB route (p95 max-load-fraction, lower is better):

- linear: `0.2695`
- random balanced: `0.2206`
- popularity round-robin: `0.2303`
- coactivation balanced: `0.1947`  (**best static**)

Static placement comparison on EB route (p95 skew):

- linear: `5.502`
- random balanced: `3.387`
- popularity round-robin: `3.697`
- coactivation balanced: `2.640`

Oracle-like dynamic lower proxy:

- dynamic LPT p95 max-load-fraction: `0.1255`

Interpretation:

- Pure placement already has large room versus linear.
- Co-activation-aware placement is significantly stronger than simple popularity placement in this trace family.
- There remains additional headroom beyond static placement if dynamic scheduling/replica is added.

---

### Stage 3 — Replica budget sweep

Base placement: `coactivation_balanced` (from Stage 2).

EB route p95 max-load-fraction:

- Base: `0.1947`
- +1% replica (3 experts): `0.1943` (`-0.00042`)
- +2% replica (5 experts): `0.1967` (`+0.00204`)
- +5% replica (13 experts): `0.1843` (`-0.01040`)
- +10% replica (26 experts): `0.1783` (`-0.01642`)

Interpretation:

- Very small replication (1~2%) is unstable/low impact with current greedy split policy.
- 5~10% hot-expert replication gives clear tail-load reduction.
- Current sweet spot candidate: start from 5% budget; evaluate runtime overhead before moving to 10%.

---

### Stage 4 — Global-prior transfer (held-out blocks)

Split:

- Train blocks: `0..4`
- Test blocks: `5..8`
- Train records: `5206`
- Test records: `4864`

Coverage transfer on held-out test (same-size expert set):

- EB `S_mask` mean coverage: `0.9687`
- train-prior mean coverage: `0.9680`
- oracle-all prior mean coverage: `0.9727`
- train-prior minus EB: `-0.00067`

Placement transfer on held-out EB route (p95 max-load-fraction):

- linear: `0.2574`
- train-prior pop-RR: `0.2442`
- oracle-all pop-RR: `0.2277`

Interpretation:

- Global prior learned on earlier blocks transfers well (coverage almost equal to online EB).
- Prior-guided placement remains beneficial on held-out blocks.
- This supports `global prior + block-local correction` as a viable system strategy.

---

## Consolidated Conclusion

1. EB-aware EPLB route is feasible and justified by current data.
2. Static co-activation-aware placement is the strongest immediate lever and should be the first source-landing target.
3. Sparse replication is useful but should start at moderate budget (around 5%) rather than very tiny budget.
4. Global prior transfer looks robust enough to support low-frequency prior refresh strategy.
5. Stage-1 direct skew-latency correlation is weak under existing coarse timing reference; if needed, run a dedicated per-layer-timed online experiment before final claim wording.

1. Implement static co-activation-aware expert placement in loading path.
2. Add 5% hot-expert sparse replication with block-local replica selection.
3. Keep EB/router semantics unchanged; only change expert placement/execution mapping.
4. Run C12 online A/B timing + quality check to convert proxy improvements into real latency deltas.
