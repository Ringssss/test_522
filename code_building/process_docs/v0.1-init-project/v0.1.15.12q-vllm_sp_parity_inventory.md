# v0.1.15.12q - vLLM SP-Parity Inventory

## Purpose

本文件用于持续跟踪 vLLM 中和 sequence parallelism / SP-MoE / SP compilation 相关的可搬组件。直到本表每一项被确认前，不应认为 vLLM SP-parity 已经完整搬运。

状态定义：

- `confirmed_moved`: 已经在 BSP 实验脚本中实现并验证。
- `confirmed_source_only`: 已经确认 vLLM 有，但当前只是源码设计参考，尚未搬运。
- `needs_source_analysis`: 需要继续读源码或对 LLaDA2 适配点做验证。
- `postponed`: 确认存在，但当前阶段不做。
- `not_applicable`: 确认不适用于当前 LLaDA2/BSP 路线。

恢复顺序：

1. 读本文件。
2. 读 `v0.1.15.12p-bsp_g2_sp_parity_bundle.md`。
3. 读 `findings.md` 中 `BSP-G2 vLLM SP-Parity Bundle Findings`。
4. 读 `code_building/key_conclusion.md` 中 `v0.1.15.12p`。
5. 只讨论和确认，不直接开始代码建设，除非用户明确要求。

## Current Anchors

当前 measured-best 性能路径仍是 BSP-G：

- A baseline C12: `75.428 ms/fwd` in latest G2 matrix.
- G: `69.676 ms/fwd`.
- G2: `69.661 ms/fwd`.
- G2 与 G 仅差 `0.015 ms/fwd`，属于噪声内持平。

G2 的结论：

- 成功把 attention-input gather 从 `moe.tp_all_gather` bucket 移到 `attn.input_all_gather` bucket。
- 没有减少通信字节或同步点。
- 因此 G2 是 source-organization / layout ownership parity，不是新的性能台阶。

## Immediate Confirmation Checklist

优先级从高到低：

1. `VSP-06`: LLaDA2 shared expert / dense MLP 在 SP 下是否还有 TP 冗余。
2. `VSP-08`: 已确认当前 backend 状态：AgRs 默认可用；FlashInfer all2all 可 smoke；DeepEP ABI-broken；PPLX absent；FlashInfer Cutlass 暂非首选。
3. `VSP-10`: 已确认环境/pass/op 前提存在，但当前 benchmark 未使用 vLLM compile pass manager。
4. `VSP-11`/`VSP-12`: 已确认 source landing 必须设计 residual scattered metadata、TP-multiple static sizes、CUDA graph mutation guard。
5. `BSP-06`: 在确认 backend 后，再决定 BSP-H/F2 是否自研 hierarchical collective。
6. `BSP-07`: 继续延长 dLLM block-iteration SP layout 生命周期，但必须逐算子确认 full/SP layout 可行性。
