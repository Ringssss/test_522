# v0.1.9-全路径性能对比与 baseline 确定

## Goal

系统性对比 dInfer 中所有可用的推理路径，在短 prompt（55 tok）和长 prompt（662 tok）下找出最快配置，作为后续缓存优化的 baseline。

## Changes Made

- 新增短 prompt 全路径对比脚本：`/home/wuhang/wuhang/dllm_wh/codex_coding/src/bench_all_paths.py`
- 新增长 prompt 对比脚本（含 IterSmooth）：`/home/wuhang/wuhang/dllm_wh/codex_coding/src/bench_long_prompt.py`
- 测试了 8 条推理路径，其中 5 条成功、3 条因兼容性问题失败

## Result

### 短 prompt (55 tok)

| 路径 | tok/s | fwd/s | forwards |
|------|-------|-------|----------|
| BD attnmask (no cache) | **76.8** | 26.9 | 48 |
| BD + prefix cache | 70.6 | 26.3 | 51 |
| BW + no cache | 53.1 | 27.4 | 66 |
| BW + dual cache | 51.9 | 26.3 | 65 |
| BW + prefix cache | 51.4 | 26.1 | 65 |

### 长 prompt (662 tok)

| 路径 | tok/s | fwd/s | forwards |
|------|-------|-------|----------|
| BD attnmask (no cache) | **75.2** | 26.2 | 48 |
| BD + prefix cache | 57.9 | **19.7** | 47 |
| BW + dual cache | 40.7 | 26.4 | 83 |
| BW + prefix cache | 39.8 | 26.1 | 84 |

### 失败路径

- BD + sglang backend：`KVCache` 缺少 `cache_align_size` 属性（需要 sglang 自己的分布式初始化）
- IterSmooth + prefix：`h2e` 中 `prob @ W_e` dtype 不匹配（float vs bfloat16），需要 cast 修复
- VicinityCache：RoPE position embedding 尺寸与窗口输入不匹配

## Key Conclusions

1. **BlockDiffusionLLMAttnmask 是确定的最快路径**：短 prompt 76.8 tok/s，长 prompt 75.2 tok/s
2. **prefix cache 在长 prompt 下 fwd/s 严重下降**（26.3 -> 19.7），cache 管理开销反而拖慢了 forward
3. **attnmask 全重算路径的 fwd/s 几乎不受 prompt 长度影响**（26.9 -> 26.2）
4. **IterSmooth 和 VicinityCache 尚未适配 LLaDA2MoE**，需要修复 dtype 和 position 逻辑
5. **torch.compile 在 torch 2.8.0 + LLaDA2MoE 上触发 InductorError**，当前不可用

## Next Steps

- 后续缓存优化的 baseline：**BlockDiffusionLLMAttnmask, threshold=0.90, 75-77 tok/s**
- 最有价值的优化方向：在 attnmask 路径基础上，对 prompt + 已完成 block 引入选择性 KV 缓存，只重算因当前 block 变化而需要更新的 KV
- 如果想让 IterSmooth 可用，需要先修 `h2e` 的 dtype bug
