# v0.1.15.12r - BSP-G3 to BSP-G7 vLLM SP Completion

## Purpose

本轮目标是按已确认的 BSP-G 后续路线，连续完成 `bsp-g3` 到 `bsp-g7`：

1. `bsp-g3`: 确认 `VSP-06 shared expert / dense MLP SP handling`。
2. `bsp-g4`: 给出 BSP-G source-downshift 设计。
3. `bsp-g5`: 验证 `VSP-10 AsyncTP / compilation-level SP` pattern-hit。
4. `bsp-g6`: 盘点 `VSP-08 MoE communication backend` 可用性与优先级。
5. `bsp-g7`: 固化 `VSP-11/VSP-12` source landing 约束。

本轮遵循新的实验归档规范：阶段开始前先写入目标/假设/风险；阶段结束后立即更新结果和结论。若过程中发生上下文压缩，应先恢复本文件、`task_plan.md`、`findings.md`、`progress.md` 和 `v0.1.15.12q-vllm_sp_parity_inventory.md`。

## Current Baseline

当前 measured-best BSP 路线仍是 BSP-G：

| Config | Latest C12 e2e |
|---|---:|
| A baseline | `75.428 ms/fwd` |
| E / C+ | `71.816 ms/fwd` |
| G | `69.676 ms/fwd` |
| G2 | `69.661 ms/fwd` |
| F probe | `72.380 ms/fwd` |

关键解释：

- G 的收益来自延长 SP layout 生命周期并让 attention output 直接 reduce-scatter 到 SP layout。
- G2 只迁移 gather ownership，不减少字节或同步点，因此不是新的性能台阶。
- 后续能拉大收益的高概率来源是 AsyncTP/fusion pattern 命中、backend 替换、或 BSP-H/F2 hierarchical collective，但后者本轮不直接实现。

## Phase G3 - VSP-06 Shared Expert / Dense MLP SP Handling

**Status:** complete

### Goal

确认 vLLM 中 shared expert / dense MLP 在 SP 下如何避免 TP 冗余，并判断 LLaDA2 当前 BSP-G 是否已经等价，还是仍有可搬性能点。

### Planned Checks

1. 读取 vLLM `deepseek_v2.py`、`llama4.py`、`qwen3_moe.py` 中 shared expert / dense MLP 的 SP 分支。
2. 读取 LLaDA2 MoE sparse block 中 shared expert 的实现。
3. 检查当前 `bench_bsp_moe_dp2.py` 的 BSP path 是否对 shared expert 使用 TP-local tokens，是否触发 Dense MLP TP all-reduce。
4. 结论写回本文件和 `v0.1.15.12q-vllm_sp_parity_inventory.md`。

### Risks

| Risk | Handling |
|---|---|
| LLaDA2 shared expert 使用普通 TP MLP 并在 SP 下触发 all-reduce | 需要设计 `disable_tp` 或 local-only shared expert 等价路径。 |
| vLLM shared expert pattern 只适用于特定模型结构 | 记录为 source-only，不强搬。 |
| monkey-patch 已经绕开 Dense MLP TP all-reduce | 标记 `VSP-06` 为 confirmed_moved 或 not_applicable，不做额外实验。 |

### Result

| Check | Result |
|---|---|
| vLLM behavior | DeepSeek/Llama4 shared expert uses TP Linear normally, but sets `disable_tp=is_sequence_parallel`; comment explicitly says SP input/output are TP-sharded and weights are replicated, so no collective is needed. |
| LLaDA2 shared expert | `LLaDA2MoeMLP` is plain replicated `nn.Linear` for `gate_proj/up_proj/down_proj`; it is not `ColumnParallelLinear`/`RowParallelLinear`, so there is no TP all-reduce to disable. |
| LLaDA2 dense-only MLP | `first_k_dense_replace=1` in `/mnt/models/LLaDA2.0-mini/config.json`, so layer 0 is dense-only `LLaDA2MoeMLP`; it is also replicated `nn.Linear`, not TP-sharded Linear. |
| LLaDA2 MoE layers | Config has `num_hidden_layers=20`, `num_shared_experts=1`, so sparse layers 1-19 each have shared expert. |
| Current BSP-G patch | All BSP paths call `shared_mod(hs_sp)` after token-axis `sequence_parallel_chunk`; shared expert computation already runs only on the TP-local token shard. |

Conclusion:

- `VSP-06` is not a missing performance component for the current LLaDA2-mini BSP-G route.
- vLLM's `disable_tp=is_sequence_parallel` mechanism matters for models whose shared expert/dense MLP uses TP Linear. Current LLaDA2 shared/dense MLP uses replicated `nn.Linear`, so there is no hidden TP all-reduce to remove.
- The source landing requirement is still important: shared expert must continue to run on SP-local tokens before any output gather. Moving it back to full layout would regress work volume.

Inventory update: mark `VSP-06` as `confirmed_not_missing_for_LLaDA2`; keep source-downshift checklist item to preserve local-token shared expert execution.

### Result

### Source Boundary

Current BSP-G/G2 monkey-patch boundaries in `codex_coding/src/bench_bsp_moe_dp2.py`:

| Boundary | Current script object/function | Source-downshift target |
|---|---|---|
| SP layout carrier | `SPHiddenState` | A small model-local dataclass or runtime carrier, not a public tensor subclass. |
| Attention SP output carrier | `AttnSPResult` | Can be internal to LLaDA2 attention/layer forward. |
| G2 attention input carrier | `SPAttentionInput` | Optional cleanup; not required for first performance source-downshift. |
| MoE token chunk | `sequence_parallel_chunk` before shared/gate/FusedMoE | Use vLLM custom op directly in LLaDA2 MoE/layer source. |
| FusedMoE SP mode | `_set_experts_sequence_parallel(experts, True, tp_size)` | Construct `FusedMoE(..., is_sequence_parallel=True)` or set once during model init under feature flag. |
| Attention output RS | `make_attention_reduce_scatter_forward` | Add an attention forward variant that replaces RowParallelLinear output all-reduce with local o_proj + `tensor_model_parallel_reduce_scatter(dim=0)`. |
| Cross-layer SP lifecycle | `make_bsp_g_attn_rs_decoder_forward` | Add decoder-layer feature path that keeps residual/post-attention/MoE output as SP until next sparse attention input or final sparse layer. |
| Attention input gather | In G: decoder gathers normalized SP input before attention. In G2: attention owns gather. | First source-downshift should use G for performance parity; G2 can be a later organization refactor if needed. |

### Recommended First Source Landing Shape

First production/source-downshift target should be **BSP-G**, not G2:

| Choice | Decision | Reason |
|---|---|---|
| Performance reference | Use G as measured-best | C12 G is effectively `69.5-69.7 ms/fwd`; G2 only ties e2e and is slower under component timing. |
| Attention input gather ownership | Keep decoder-side gather in first source landing | This matches measured-best G exactly and avoids introducing a source refactor that has not shown speed benefit. |
| Attention output layout | Add native `return_sp_output=True` / `bsp_attn_reduce_scatter=True` path | This is the actual G speed mechanism. |
| MoE output gather | Gather only at the final sparse layer or when a full-layout consumer requires it | This preserves cross-layer SP lifecycle. |
| EB/s_mask | Keep routing function unchanged | G already preserves C12 path counts. |
| Scheme3 / M3 payload | Exclude | Not part of BSP-G source-downshift. |

### Minimal Source Design

Proposed feature flags:

| Flag | Scope | Meaning |
|---|---|---|
| `config.use_bsp_sequence_parallel_moe` | model/config | Enables BSP-G source path for sparse decoder layers. |
| `config.bsp_sp_attention_output` | attention/layer | Allows attention o_proj to return token-axis reduce-scattered output. |
| `config.bsp_gather_at_sparse_boundary` | decoder layer | Controls gather on last sparse layer or before non-SP consumers. |

Proposed source flow for sparse decoder layers:

1. If input is full layout `[bsz, seq, hidden]`, keep a full tensor for attention input norm and also compute `residual_sp = sequence_parallel_chunk(residual_flat)`.
2. If input is `SPHiddenState`, run `input_layernorm` on `hidden_sp`, then all-gather normalized hidden before attention. This is the current G measured path.
3. Run attention in full layout, but replace the attention `RowParallelLinear` output all-reduce with `tensor_model_parallel_reduce_scatter(output_parallel_flat, dim=0)`.
4. Add residual in SP layout: `hidden_after_attn_sp = residual_sp + attn_sp`.
5. Run post-attention norm, shared expert, gate logits, and `FusedMoE.forward_impl` on `hs_sp`.
6. Keep `hidden_sp = hidden_after_attn_sp + moe_sp` across sparse layers.
7. On the last sparse layer, or before any full-layout-only consumer, `tensor_model_parallel_all_gather(hidden_sp, dim=0)` and trim to `N`.

### Required Invariants

| Invariant | Check |
|---|---|
| Token count | `N = bsz * seq_len`; `N_sp = ceil(N / tp_size)`; trim gathers to original `N`. |
| FusedMoE metadata | `set_forward_context(..., num_tokens=N)` must cover each SP MoE call so `dp_metadata.sp_local_sizes(tp_size)` is correct. |
| EB path counts | C12 must remain `prefill_fallback=19,cold=171,hot_skip=3933,hot_update=931`. |
| Shared expert | Must run on `hs_sp`, not full `hs_flat`. |
| Attention output | Must reduce-scatter the local RowParallelLinear result over token axis; falling back to normal `dense(attn_output)` loses G. |
| Last sparse boundary | Must gather before LM head / non-SP downstream logic. |

### First Files to Touch Later

This phase does not edit source mainline yet. If/when source landing starts, the likely files are:

| File | Role |
|---|---|
| `lib_cite/dInfer/python/dinfer/model/modeling_llada2_moe.py` | LLaDA2 attention, decoder layer, MoE block, SP carrier. |
| `codex_coding/src/bench_bsp_moe_dp2.py` | Keep as benchmark reference; eventually reduce monkey-patch once source path exists. |
| `codex_coding/src/baseline_optimizations.py` | Only if existing optimization hooks conflict with source path. |

Conclusion:

- G4 does not require immediate code sinking; the correct next move is to keep G as source-downshift target and continue checking compiler/backend opportunities first.
- G2 should remain a source-organization reference, not the default landing path, unless later compiler/backend integration requires attention to own the input gather.

Important nuance:

- A bare `torch` import initially showed no `symm_mem.fused_*` ops. Those ops become visible after importing vLLM's `collective_fusion` module.
- Direct runtime import without the benchmark's `sys.modules["deep_ep"] = None` guard can fail because installed `deep_ep._C` references missing `ncclTeamWorld`.
- Therefore, AsyncTP is **environment-present but not currently consumed** by the standalone BSP-G benchmark.

Conclusion:

- `VSP-10` is a real candidate, not a dead end: the necessary vLLM passes and fused symmetric-memory ops are importable in this environment under the same DeepEP guard used by the benchmark.
- Current BSP-G/G2 source shape is conceptually close to the two AsyncTP patterns:
  - G: local attention output GEMM followed by token-axis reduce-scatter.
  - G2: token-axis all-gather followed by QKV/GEMM.
- But current monkey-patch benchmark does not route through vLLM V1 compilation / Inductor pass manager, so no AsyncTP fusion is actually being applied today.
- To realize this benefit later, source landing must either:
  1. Move BSP-G into a vLLM-compiled graph using `torch.ops.vllm.reduce_scatter/all_gather` and `enable_async_tp`, or
  2. Manually call/replicate the equivalent fused symmetric-memory ops after proving correctness and shape constraints.

Recommendation:

- Do not change the benchmark mainline yet.
- Preserve G/G2 source shapes during source-downshift because they are plausible future pattern-hit shapes.
- Treat AsyncTP as a post-source-downshift acceleration layer, not as something already active in current experiments.

- `VLLM_ALL2ALL_BACKEND` default is `allgather_reducescatter`.

### Result

### vLLM Source Constraints Confirmed

| Constraint | vLLM evidence | BSP-G source landing implication |
|---|---|---|
| Residual scattered is conditional | `is_residual_scattered_for_sp()` returns true only when `enable_sequence_parallelism`, `tp>1`, `num_input_tokens % tp == 0`, and `num_input_tokens in compile_sizes`. | Source landing must carry explicit SP/full layout metadata; do not infer layout from tensor shape alone. |
| SP capture sizes must be TP multiples | `update_sizes_for_sequence_parallelism()` removes capture sizes not divisible by TP size. | Any CUDA graph/static-size plan must only capture token counts divisible by TP. |
| Runtime pads for SP | GPU runner rounds token count up to TP multiple when sequence parallelism is enabled outside CUDA graph path. | BSP source path must trim all-gather outputs back to original `N` and preserve `N_original`. |
| PP/intermediate residual transfer is layout-aware | vLLM sends/receives `residual` without TP all-gather only if `is_residual_scattered_for_sp()`. | If source landing later touches PP/intermediate tensors, the `residual` key must be explicitly marked scattered. |
| CUDA graph forbids forward-time buffer mutation | vLLM compiler wrapper raises if cudagraph mode sees `update` buffer mutation in forward. | Avoid mutating module buffers or layout state during forward; SP layout should be carried by values/context, not module-global mutable flags. |

### BSP-G Source Landing Checklist

Must-have for first source landing:

| Item | Requirement |
|---|---|
| Feature flag | Add an explicit BSP/SP flag; default off. |
| Layout carrier | Carry `hidden_sp`, `bsz`, `seq_len`, original `N`, and `tp_size`; treat it as internal metadata. |
| Full/SP boundary | Gather only before full-layout consumers: attention input in G, last sparse layer output, LM head/logits, quality decoder. |
| Attention output | Implement attention o_proj local compute + token-axis reduce-scatter without the normal RowParallelLinear all-reduce. |
| MoE SP mode | Construct or initialize FusedMoE with `is_sequence_parallel=True`, `sp_size=tp_size`; avoid per-forward mutable monkey-patching. |
| ForwardContext | Wrap every SP MoE call with correct `num_tokens=N` so DP metadata and chunk sizes are correct. |
| Shared expert | Run shared expert on `hs_sp`; never on full `hs_flat` in BSP-G. |
| EB/s_mask | Keep routing path unchanged; require C12 path counts invariant. |
| Shape | Require or pad to `N % tp == 0`; trim gather to original `N`. C12 `N=8192`, `tp=4`, `N_sp=2048` is safe. |
| Fallback | If unsupported layout/shape/backend is encountered, fall back to existing full-layout path without changing EB state. |
