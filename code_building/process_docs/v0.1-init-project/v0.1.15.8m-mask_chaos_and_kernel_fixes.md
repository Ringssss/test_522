# v0.1.15.8m — mask_chaos 探索 + MAX_ROUNDS 修正 + 物理 Token 分离

## 归档时间：2026-04-20
## 阶段：v0.1-init-project / v0.1.15.8m

## 1. 本轮概述

在 v0.1.15.8l（batch=128 组件级 profiling + expert 使用模式采集）基础上，进行了三个方向的深入探索：
1. mask_chaos 计划：低置信度 MASK token 的 MoE 计算是否可以简化/跳过
2. MAX_ROUNDS 完备性修正：从 16 提升到 27，保证算法可覆盖全部 256 expert
3. Weight Compaction 验证：紧缩 expert 权重是否能加速 fused_experts

## 2. MAX_ROUNDS 修正（★ 已合入 test_fused_eb_triton.py）

### 发现
- 旧 MAX_ROUNDS=16: 上限 K_target + 16×cap = 40+128 = 168 < 256（不完备）
- 诊断数据：avg 实际需要 17.2 轮，max=23 轮，68.4% 的冷启动需要 >16 轮
- K_C kernel 已有 sat_flag 提前退出（无需 CPU sync），K_D_v2 也有

### 修改
- MAX_ROUNDS: 16 → 27（40 + 27×8 = 256，理论完备）
- K_init: 从理论上限改为 `actual_s = int(b['s_mask'].sum().item())`
- 性能验证：C10-M∞ = 12.14s (-2.3% vs C5)，C10-M5 = 12.02s (-3.3% vs C5) — 和旧版一致

### 诊断数据（diag_smask_rounds.py）
- |S| avg=165.6, min=120, max=216
- L0/L1 需要 200+ expert（浅层 routing 最分散）
- L17 需要最少（avg=150.9）
- 按轮次分布：Round 17-18 是峰值（各 22%），Round 11-16 占 33%

## 3. Weight Compaction 验证

### 结果
- Original [256, auto-tuned]: 1.771ms
- Compact [158, default config]: 3.198ms (+80.6%)
- 根因：vllm 只有 E=256 的 auto-tuned kernel 配置，非标准 E 回退到 default config

### 关键认知
- S_mask 不改变 weight tensor 大小（仍 E=256），只控制 topk_ids 内容
- vllm E=256 tuned kernel 在稀疏使用下已高效（不加载不在 topk_ids 中的 expert）
- Compaction 方向在当前 vllm 架构下不可行

## 4. mask_chaos 计划（★★★ 核心探索）

### 4a. 初始假设
低置信度 MASK token 在"浮游状态"，其 routing 可能不重要，可以简化/跳过 MoE 计算。

### 4b. 发现 vllm fused_experts 的 inplace=True（★★★ 关键 bug）
- vllm `forward_cuda` 调用 `fused_experts(x, w1, w2, ..., inplace=True)`
- 这意味着 `forward_impl(hs_flat, logits)` 会原地修改 hs_flat
- 之前所有 torch.where 替换实验中，`identity = hs_flat * weight_sum` 实际用的是**已经被 inplace 修改的 hs_flat**（即 routed output），不是原始 hs
- 导致 skip token 实际得到 `routed_output × rsf`（接近正常输出），而非 `original_hs × rsf`（真正的 identity）
- **之前 skip<0.6 的 "5/5 质量 PASS" 全部是假阳性**

### 4c. 修正后的 identity skip 验证（test_mask_chaos_skip_v3.py）
用 `hs_original = hs_flat.clone()` 保存原始值后重测：
- skip<0.3 (37.4%): 质量崩溃（中英混杂、乱码）
- skip<0.5 (77.8%): 完全崩溃
- **结论：真正的 identity pass-through 在任何 threshold 下都不安全**

### 4d. Random Routing 验证（test_mask_chaos_routing.py）
- rand<0.3 (29.5%): 4/5 质量（#28 轻微混乱）— 不受 inplace bug 影响
- rand<0.5 (38.9%): 3/5（开始退化）
- rand<0.6 (45.8%): 1/5（严重退化）
- fixed8<0.3 (29.7%): 4.5/5（和 random 类似）
- **结论：安全边界在 threshold≈0.3，~30% token，质量勉强可接受但不完美**

### 4e. Top-1 Concentration 验证（test_mask_chaos_top1.py）
低置信 token 全部路由到自己的 top-1 expert（8 个 slot 全填 top-1 ID）：
- top1<0.3 (41.3%): 2/5 质量 — 比 random 更差
- unique expert 确实减少：168 → 150.3（-10.5%）
- **结论：需要 multi-expert 多样性，top-1 太激进**

### 4f. mask_chaos 总结论
- **低置信 token 必须经过真正的 expert 非线性计算**（identity skip 不可行）
- **routing 选择有一定容忍度**（random routing conf<0.3 勉强安全）
- **但安全窗口太窄（~30%），ROI 不足以工程化**
- **该方向关闭，回到 C10-M5 基础优化**

## 5. Routing 分散度分析（collect_routing_dispersion.py）

### 关键发现
- 浅层（L0-L11）：低置信 token 的 max_sigmoid 显著低于高置信 token（差 0.15-0.40）
- 深层（L15-L18）：**完全反转**！低置信 token 的 max_sigmoid 反而更高
- 解读：深层对不确定 token 投入更多 routing 注意力（尝试"搞清楚"token 该是什么）
- 选择性：max_sigmoid < 0.3 时 LowConf 命中率是 HighConf 的 9.6 倍

## 6. 两级 Skip 验证（test_two_level_skip.py）
Tier1(confidence) + Tier2(per-layer routing dispersion)：
- Tier2 增量贡献仅 1.6%-4.4%（per-layer routing 信号在 Tier1 之上增量很小）
- flat skip 已经足够好，两级方案增加复杂度但 ROI 不足
